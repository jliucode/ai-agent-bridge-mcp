# AI Agent Bridge MCP - 技术架构说明

> 版本: 1.0.0
> 更新日期: 2026-05-02

## 1. 概述

### 1.1 背景

原 AI Agent Bridge MCP 设计存在核心问题：Claude Code 作为按需启动的对话工具，无法实现"自动心跳"、"自动状态切换"等常驻 Agent 功能。用户不发消息 → Claude Code 不运行，无法保持长连接监听 SSE 事件。

### 1.2 解决方案

引入 **Client-Side MCP Proxy（本地 MCP 代理）** 作为常驻进程，解决以下问题：

| 问题 | 解决方案 |
|------|----------|
| Claude Code 无法自动心跳 | MCP 代理作为常驻进程，自动发送心跳 |
| 无法实时接收任务推送 | MCP 代理保持 WebSocket 连接，通过 Channel 推送给 Agent |
| 无法跨机器共享能力 | MCP 代理同步远程 Agent，包装成动态 MCP tools |

### 1.3 核心理念

```
多台机器上的 Agent 上报自己的功能 → 形成 MCP 功能池子
本地常驻 MCP 服务把这些功能包装成 MCP 技能提供给用户
```

### 2.2 四步渐进式设计

```
Step 1: 托盘应用启动
├── MCP 代理启动
├── 上报机器 IP
├── 建立 WebSocket 连接

Step 2: Agent 自注册
├── Agent 调用 agent_register tool
├── MCP 代理生成唯一 ID (project-PID-hash)
├── 上报项目名 + 技能列表
├── Bridge 注册成功

Step 3: 动态 MCP 包装
├── MCP 代理同步 Bridge 的 Agent 列表
├── 包装成 remote_skill tool
├── Agent 可调用远程技能

Step 4: Agent 重载
├── Agent 重新加载 MCP
├── 获取在线的全部 tools
├── 功能池共享完成
```

## 6. 核心机制

### 6.1 Agent ID 生成规则

```python
# 格式: {project}-{PID}-{short_hash}
# 示例: web-app-12345-a3f2
def generate_agent_id(project: str, pid: int) -> str:
    short_hash = hashlib.md5(
        f"{project}{pid}{time.time()}".encode()
    ).hexdigest()[:4]
    return f"{project}-{pid}-{short_hash}"
```

**特点：**
- 项目名前缀，便于识别
- PID 区分同项目多进程
- short_hash 确保唯一性

### 6.2 存活检测机制

| 方案 | 优先级 | 适用场景 |
|------|--------|----------|
| **Session 连接状态** | Phase 2 实现 | Claude Code（MCP stdio 连接），断开自动 OFFLINE |
| **PID 存活检测** | 备用方案 | 非 Claude Code Agent，或 session 检测失效时 |

```python
# Session 断开检测
def on_session_disconnect(session_id: str):
    agent_id = self.sessions.get(session_id)
    if agent_id:
        self.mark_agent_offline(agent_id)
        del self.sessions[session_id]

# PID 检测（备用）
async def pid_check_loop(self):
    while True:
        for agent_id, info in self.agents.items():
            if not psutil.pid_exists(info["pid"]):
                self.mark_offline(agent_id)
        await asyncio.sleep(60)
```

### 6.3 心跳机制

| 层级 | 心跳机制 | 间隔 |
|------|----------|------|
| MCP 代理 → Bridge | WebSocket `machine_heartbeat` | 每 30 秒 |
| Agent → MCP 代理 | **无心跳**，session 连接状态检测 | - |
| Bridge → Agent 状态超时 | WebSocket 断开 → 全部 OFFLINE | - |

### 6.4 本机 vs 远程文件处理

| 场景 | 目标位置 | 文件处理 |
|------|----------|----------|
| **本机调用** | 同一 MCP 代理下的 Agent | 直接传路径，无需传输内容 |
| **远程调用** | 其他机器的 Agent | Base64 编码 → WebSocket → 远程保存 |

```python
# 本机调用
if is_local_agent(target["agent_id"]):
    # 直接传递本机路径
    params["files"] = files  # 不读内容

# 远程调用
else:
    # 读取并编码
    file_data = FileTransfer.read_files(files)
    params["files"] = file_data  # Base64 编码
```

## 7. LLM 智能调度

### 7.1 两层 LLM 职责

| 层级 | LLM 职责 | 决策场景 |
|------|---------|----------|
| **Bridge LLM** | 全局路由 | 任务委派选择最佳 Agent、远程技能调用匹配 |
| **MCP 代理 LLM** | 本地优化 | 本机多 Agent 选择、结果格式化、错误诊断 |

### 7.2 Bridge LLM 路由决策

```
任务委派请求
    ↓
基础过滤（按 project/skill 筛选）
    ↓
LLM 分析：
  - 任务描述
  - 技能需求
  - 候选 Agent 列表
  - 选择标准（技能匹配、状态优先、项目相关性、负载均衡）
    ↓
返回选中 Agent + 理由
    ↓
失败？ → 降级到负载均衡
```

### 7.3 失败降级策略

| 场景 | 降级方案 |
|------|----------|
| LLM 调用超时（>5秒） | 使用负载均衡策略（最少任务） |
| LLM 返回无效 JSON | 使用负载均衡策略 |
| LLM API 错误 | 使用负载均衡策略 |
| LLM 未启用 | 直接使用负载均衡策略 |
| 置信度 < 0.5 | 使用负载均衡策略 |

## 11. 技术要点备忘

### 11.1 Channel 实现

- **Capability declaration**: `experimental: { 'claude/channel': {} }`
- **Notification format**: `notifications/claude/channel`
- **启动命令**: `claude --dangerously-load-development-channels`

### 11.2 Channel 限制说明

| Channel 能做到 | Channel 做不到 |
|----------------|---------------|
| ✅ 推送消息到 Agent 终端 | ❌ 强制 Agent 自动调用 tool |
| ✅ Agent 自动看到内容 | ❌ Agent 自动执行操作 |
| ✅ 用户无需刷新/轮询 | ❌ 替代用户指令 |

**实际工作流程：**
1. Channel 推送到达 → Agent 展示给用户（自动）
2. 用户看到消息后输入指令（如 "查看任务详情"）
3. Agent 调用 `get_pending_tasks`
4. 用户继续输入（如 "开始处理"）
5. Agent 调用 `task_update` 并执行任务
